# Project intelligence

The runtime controller, worker and analyzer are aligned to merged Common `a311b0fb18065584bcbd9948170a8512ebc9087f`, matching the existing vendored host package. Python 3.13.15 and SQLGlot 30.19.0 binaries remain unchanged. The former runtime pin contained the older controller protocol and lacked the current analyzer. Project analysis uses the host's exact captured-snapshot entry point so notebook projections and masked syntax are bound to their acquired bytes. LPAC, Job Object, parser guards and result validation remain enforced. Qualification uses the installed VSIX, rather than treating historical Common containment results as a new verification.

Open **DataPass: Open Home** for the project map, repository revisions, declared scope groups, logical environments, local readiness and lineage coverage. Environment selection uses the existing manifest and persists in this workspace. Names are arbitrary; production flags, non-secret identifier maps, targets, links and local prerequisites come from declarations and existing preflights. Local readiness does not attest deployment.

**Analyze project locally** is an explicit action on a trusted local workspace with saved source. It reads bounded source snapshots and invokes installed, pinned extractors. It never runs project Python/SQL, a notebook, an orchestration job, a cloud deployment or an AI. The source hash and repository-relative locator remain attached to evidence. Source edits, filesystem changes and refresh invalidate the report. Reload keeps the environment selection and clears the analysis; analyze again to obtain a fresh graph.

The published analyzer SPI and lineage-core canonical identities feed one LG0 graph. Navigator, its existing lineage/data-flow bindings and eight Hop projections consume this graph: architecture, data, columns, orchestration, deployment, downstream impact, quality/tests and environment applicability. Environment applicability comes from component files and operations declared for the selected environment. Unmapped sources remain a visible gap. A selected canonical node stays available as context across projections.

Coverage reports UNDERSTOOD, PARTIAL, UNKNOWN and IGNORED. Generated/dependency/local metadata directories, links, acquisition failures, limits and unavailable repositories are explicitly reported. Default bounds are 5,000 relevant files, 5,000 directories, 12 directory levels, 2 MiB per file and 64 MiB per repository. Credential files are classified without reading their values. Bounded coverage is not a completeness guarantee.

Native parser failures retain bounded host codes in the report's gaps, without paths, source, stderr or arbitrary exception messages. CI qualifies the native V6 fixture first, then runs all twenty existing desktop fixtures in shards and the UI checks. This isolates parser qualification from competing launches while keeping every fixture mandatory.

Evidence labels preserve **static-parse**, **artifact-import**, **runtime-observed**, **ai-proposed** and **ai-confirmed** separately. Home counts every origin represented on an edge; the graph's expandable evidence list retains mixed origins and source references. Imported or observed evidence does not become a DataPass observation. This increment does not add a runtime collector or a new external graph import protocol.

Generated paths reuse NavTours and Steps: overview, engineering, Spark/notebook, BI, deployment, change review and interview. A path is offered only when relevant components exist. Visiting a step does not create verification. Notebook/Spark explanation is explicitly declared/conceptual, with local file and operation context; it makes no runtime performance claim.

The repository → component Sankey reuses the graph renderer. Weight is one declared component, independent of effort/productivity. Existing repository-history Sankey remains available. Additional theme/family/changed-file Sankey modes are a later increment.

Optional registered companion commands appear in Home. `datapass.project-navigation/1` passes bounded canonical IDs, source references, revisions, environment and provenance to Cloud Studio, X-Ray or Tern for inspection/planning. Absent commands are hidden and rejected if invoked. These proposed payloads still require qualification with the real companion extensions; core use requires none of them.

Preservation/history audits, Mongo, Harness, full Tern topology, live Spark monitoring and provider writes are outside this increment.
