# 0.25 V-A — Active variant (release notes for R2)

## What changed
- **Active variant**, machine-local and per project: `src/core/project/activeVariant.ts` (pure: store, fallback, switcher choices, pack line, status text) and `src/work/activeVariantCommands.ts` (status-bar item, `DataPass: Switch the Active Variant`, `datapass.setActiveVariant <scenario>`).
- The active variant **is the architecture preview made persistent**: VS Code global state `datapass.v25.activeVariant`, keyed by project id (the folder when there is no manifest), at most 100 projects. Every switch of the preview (status bar, Workbench selector, diagram) is remembered; on reopening, the remembered one is applied. With no entry yet, the window's existing preview is kept (0.15–0.24 behaviour). A vanished scenario or option → back to current, one information message.
- It drives what already followed the preview: Project tree (*Selected architecture*), diagram, Details, Workbench. The Workbench banner says *Active variant: …* ("this machine only") and the selector *Variant: …*.
- Packs: *Copy Context for My AI*, the options export / compare / apply packs and the options work orders get one line `Active variant (this machine's working choice, not a decision): **…** — coding state: …`.
- Surface `status.activeVariant` (Standard, DataPass, Advanced); settings override added.
- Public example `examples/v3/doc-pipeline` (options A direct script / B Blob event + Function / C Data Factory in a planned repository; dated per-currency prices, one EUR line). Guide page `docs/guide/10_SWITCHING_VARIANTS.md` (+ README line).

## Tests
- Unit `tests/activeVariant.test.ts` (6): example valid (runtime + schemas, no FOIL string), A→B→C changes the orchestration component and files, pack header in file context and options packs, switcher list and states, store survives a reload / bounded / malformed dropped / example files unchanged, fallbacks.
- Desktop: new fixture `v25-doc-pipeline` (the example as a Git repository) and flow `tests/integration/activeVariantFlows.ts`: status item, switch via the quick pick, tree and Details follow, Copy Context names B with "partly coded", C "not coded", back to current forgets, `git status` clean. v3-research and v22-modes green too. `npm run verify` green (424).

## Limits
- Readiness / Tools & versions rows are still computed for the whole project, not filtered to the active variant's components (needs a session change; next pass).
- Board card packs don't carry the line; only the options-based work orders do.
- One-line hooks outside the row's file list: `src/work/fileContextCommands.ts`, `src/work/optionsCommands.ts`, `src/work/workOrderCommands.ts`, `scripts/desktop-test.ts` (fixture), `package.json` (commands + setting), `resources/experience/presets.json`, `schemas/datapass-experience.schema.json` (regenerated).
- For brevity the example keeps its code beside `.datapass/` (its README says a real project uses native repositories).
