# Mongoku — deferred compatibility note

Mongoku development is paused. No Mongoku code, database, sync job or deployment is requested in this V2.1 pass.

When it resumes, DataPass can emit a versioned, sanitized **projection**, not a second project authority. Useful fields: organization/project/workspace/item IDs; architecture revision/status; planned capability matrix; observed implementation/runtime states with timestamps; artifact references/digests; dependencies; external work-item refs; blockers/next action; authority/source references; snapshot identity.

Do not include secrets, raw environment values, private CAD/study payloads, local paths or every log/run record. Do not duplicate FOIL PM backlog or accepted engineering facts. Keep read-model ownership explicit and distinguish user declarations from provider observations.

The generic item/artifact/binding/receipt concepts in V2.1 are sufficient to prepare this seam. Future transports may be a reviewed Git artifact, authenticated API or controlled DATAPASSCONTROL ingestion. No current cloud database requirement follows from this future option.

Mongoku provides the global portfolio view; DataPass provides scoped developer work and native-tool preparation. The same object may have a concise global summary and a rich local view without becoming two independently editable truths.
