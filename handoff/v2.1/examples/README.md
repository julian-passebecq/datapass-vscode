# Design examples

- `notebook.item.json`: one logical analysis notebook, separate purpose/language/native format, Databricks source and a Fabric candidate target. No runtime-equivalence claim.
- `airflow.item.json`: one logical DAG with local Compose, OCI/K3s and managed Fabric profiles. These are mutually selectable unqualified candidates, not three active schedules.
- `foil-domain.item.json`: optional company-specific parameter-form metadata, external schema/kernel ownership and artifact impact. No private case values, no arbitrary executable plugin and no Core Truth promotion.

All references are illustrative or explicitly to-be-bound. These files must not be pasted into the current V1 manifest importer as runnable configuration. Their role is to make the design concrete for Claude and to test the basic type/facet separation.
