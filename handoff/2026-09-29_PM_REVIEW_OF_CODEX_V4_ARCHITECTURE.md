## 1. BLOCKERS

**B1. The first-slice SQL/Python parsers cannot run in the runtime the architecture defines.**
- Where: TARGET §1 Common row, §2 ABI, L0 l.1716-1719 ("Pinned SQLLineage/sql-datalineage and existing candidate parser"), A0, A1 security l.373, A2, P1 `src/analysis/workerHost.ts`; LINEAGE_DONORS; ADR-0007 §3/§6, ADR-0008 §1/§9; FAC §12-13, CE §2/§18. Found by 01-B2, 03-M7, 04-M3, 05-M5, 06-B1.

Shortlist at least two JS/WASM SQL options and a tree-sitter-python WASM grammar for A2 (see I1). Keep sqllineage/sql-datalineage/sqlglot as **CI differential oracles only**, never shipped. State the packaging rule: WASM and grammar assets are copied by `esbuild.mjs` into `dist/` (`.vscodeignore` excludes `node_modules/**`). Delete "existing candidate parser" or name it. If a Python runtime is ever admissible, that is Q4 for Julian.

**B4. Evidence cannot express real vs simulated vs synthetic vs AI-proposed origin, and has no attestation.**
- Where: ADR-0003 `Evidence`/`Claim`, ADR-0005 §1/§8 `Qualification`, ADR-0006 §7, ADR-0007 §8, ADR-FACTORY ("rows*128 MUST NOT enter observed metrics", verified at Mosaic `work.py:137`); CE §4 Basis, §14, §30. Found by 02-M4, 03-B2, 03-M2, 04-M7.
- What: `Evidence` only has `environment` and `acquisition`; "illustrative" exists only on `Claim.method`. A simulated Fabric job fixture serializes byte-identically in shape to a real capture. `Qualification` has no origin. "JSON shape does not establish authenticity" and "do not sign simulated records" imply attestation, but none is designed. CE Basis has no AI value and §14 files "user/AI proposals as declared/inferred"; `SemanticEnrichmentProposal.answers` carries only `uncertaintyId`, so it can be applied to a newer analysis.
- Why: the rule "simulated evidence cannot satisfy provider qualification" has no field to test, and AI output can be laundered into human-declared basis.
- Fix (in C2 before any producer exists): required `origin: real | simulated-engine | synthetic-data | fixture | ai-proposed | unknown`, non-widenable through `parentEvidenceIds` (schema test); separate `dataClass: client | synthetic-L0 | sanitized | unknown`; `attestation {acquiredBy: hostId+adapterVersion, requestId, endpointAllowlistId, responseSha256, tlsHost}` minted only by an acquisition host, manual imports `unattested` (displayable, never gate-satisfying). Every gate predicate requires `origin === 'real'` and a trusted attestation. AI proposals carry basis `proposed` and `basedOn {analysisDigest, sourceDigests}`; mismatch is rejected; the validator refuses `observed/captured/static` from AI.

**B5. Review, qualification, suppression and not-applicable records can self-authorize through imported files.**
- Where: ADR-0008 §3 `ClaimReview.reviewer: string`, §4 suppressions, §6 `not-applicable`; ADR-0005 `Qualification`; repo rule "Imported approval/status labels cannot authorize themselves". Found by 03-B3; related 02-I3.

**B6. No canonical digest, path or ID specification.**
- Where: ADR-0003 `inputHashes`, `configHash`, `contentSha256`, `SourceAnchor`, ids; ADR-0008 (legacy LF-normalized vs V4 exact bytes); CE §3, §20, §21; plan Phase 2 "stale hash state agrees"; C3. Found by 02-M5, 03-M12, 04-B2, 05-m3, 06-m2.
- What: digests carry no algorithm tag and there is no canonical JSON, so two producers hash the same config differently. No `schemaVersion` on Evidence/Claim. ID generation for Evidence/Claim and namespace allocation are undefined. With `core.autocrlf=true` working-tree bytes differ from the Git blob, so one commit hashes differently on Windows and Linux. Paths have no canonical form (separators, case, NFC/NFD; `Orders.sql`/`orders.sql` collide on Windows). An exact-byte `.ipynb` hash changes on every run (outputs, execution_count). V1-derived artifactIds are path-derived, so a rename changes identity. Plan Phase 2's acceptance is unsatisfiable when V3 (LF, inclusive lines) and V4 (exact bytes, half-open UTF-8) are compared literally.
- Why: staleness, cache keys, determinism and cross-host conformance all depend on this, and every C-packet writes hashes.
- Fix: a normative "Digest and identity" section in C2 (full design in I4): `algo:hex` digests; RFC 8785 JCS for JSON; declared digest mode (`exact-bytes | lf-normalized-text | git-blob-oid`) recorded in the anchor (`anchor.encoding`); per-format `sourceSha256` for notebooks (ipynb cells' source; Fabric `# CELL` blocks; Databricks `# COMMAND`) as the invalidation key, byte hash kept for integrity; canonical repo-relative POSIX NFC paths, rejection list, `repo.case-collision` finding; content-addressed ids from (namespace, producer, inputs) with a namespace registry; `schema: 'datapass.evidence/1'`; V1-derived `artifactId = <projectId>/<repoKey>/<path>` tagged `identity: 'path-derived'` with an unstable-identity diagnostic. Rewrite Phase 2 acceptance as "staleness verdicts agree when both digests derive from the same captured bytes".

## 4. IMPROVEMENT axes

**I1. Parser runtime: JS/WASM in the host, Python as CI oracle.** Evaluate in L0, on the synthetic corpus of M20, with dialect coverage for T-SQL (Fabric Warehouse), Spark SQL/Databricks and DuckDB: (a) a JS dialect-aware SQL parser such as `node-sql-parser` (check its T-SQL/Hive/Spark coverage and column-lineage extractability); (b) `web-tree-sitter` with tree-sitter SQL and **tree-sitter-python** WASM grammars (error-tolerant, incremental, good for PySpark call-graph extraction and embedded-SQL anchors); (c) DuckDB-WASM's `json_serialize_sql` for the DuckDB dialect only; (d) Pyodide + sqlglot as a last resort, only with measured VSIX bytes and cold-start budget and Julian's consent (Q4). In CI, run sqlglot (`sqlglot.lineage`) and sqllineage as differential oracles over the same corpus and fail on unexplained divergence. Record per candidate: licence, bytes, cold start, dialects, column-lineage support, error tolerance.

**I2. OpenLineage alignment.** Use OpenLineage dataset naming (namespace + name per platform) for `LogicalEntityId`, the columnLineage facet transformation types (DIRECT: IDENTITY/TRANSFORMATION/AGGREGATION; INDIRECT: FILTER/JOIN/GROUP_BY/SORT/WINDOW/CONDITIONAL) for `LineageEdge.transform`, and run/job facets for evidence. Import and export become lossless for columns, and the OpenLineage Spark listener and Unity Catalog lineage (I10) plug in without a mapping layer.

**I3. Logical vs revision identity.** Three layers: `LogicalEntityId` (stable, dialect-normalized), `ArtifactRevision` (artifactId + content digest), `Observation` (edge/evidence binding a logical id to the revisions that asserted it). A snapshot is a manifest hash over artifact revisions. Joins across files and commits happen on logical ids; staleness on revisions.

**I4. Canonical digest spec (one page in C2).** Format `sha256:<hex>`; JSON via RFC 8785 JCS; declared modes `exact-bytes | lf-normalized-text | git-blob-oid` (recommend git-blob-oid for tracked files: stable across `autocrlf`); notebook `sourceSha256` rules per format; path canon (repo-relative, `/`, NFC, index case; reject `..`, absolute, drive letters, ADS, reserved names); id = `sha256(JCS{namespace, producer, kind, inputs})`; namespace registry; golden vectors (CRLF file, BOM file, NFD name, case pair, ipynb with outputs) run by every consumer.

**I5. DuckDB sandbox profile.** Separate read-only connection; after required ATTACH: `SET allowed_directories=[…]`, `SET enable_external_access=false`, `SET autoinstall_known_extensions=false`, `SET autoload_known_extensions=false`, `SET lock_configuration=true`; single statement via `extract_statements`, type SELECT only, row limit, no `EXPLAIN ANALYZE`; extensions pre-installed and pinned; `memory_limit` + OS Job Object for RSS; per-file cross-process lock for writers.

**I6. Milestone-closure machine check.** Per packet: `milestone`, `phase`, `productSurface (datapass|cloud|factory|hub|studio|central)`, `size`, `contextBudget`, `doneCheck`. Split the validator into `validate_structure` (today) and `validate_product_order`: closure(milestone) ⊆ this and earlier milestones; no phase ≥ 2 packet before R1a; every packet scheduled or `unscheduled`; ids in Blocked-by/contracts consumed are ancestors; size ≤ 30 M; orphan producers (A2 before B3) flagged. Publish the V4.0 critical path from the DAG (M0→C1→C2→A0→L0→A1→DQ1→P1→AI1→Q2→R1a) with sizes. Print which claims are re-executed and which come from stored JSON.

**I7. Contract single-owner table.** `ownership/contracts.json` rows: type/schema id → package → writer repo/packet → consumers → version → status. CI fails on duplicate writers, unregistered packages, reserved-name clashes across repos (`@datapass/contracts` in Mosaic), and consumer redeclarations (P4 CapturedPlan, AI1/T1 Proposal).

**I8.
